# 03. Map: платим памятью за удобный поиск

Операции чтения и записи в `map` обычно рассматриваются как O(1) в среднем. Это практическая модель, а не обещание спецификации Go для каждого отдельного случая. Порядок обхода `map` не гарантирован.

## 03.1 `Frequencies`

**Что тренируем.** Используем значение как ключ, количество — как значение map.

**Как рассуждать.** Для каждого `value` выполняем `counts[value]++`. Чтение отсутствующего ключа `int` даёт ноль, поэтому отдельная инициализация счётчика не нужна.

**Мини-пример.** `[5,2,5,5] → map[5:3 2:1]`.

**Частая ошибка.** Объявить `var counts map[int]int` и начать запись: запись в nil-map вызовет panic. Нужен `make`.

**Сложность.** Ожидаемое время O(n), память O(k), где k — число разных значений.

## 03.2 `FirstIndex`

**Что тренируем.** Отличаем первый индекс от последнего.

**Как рассуждать.** Перед записью проверяем, существует ли ключ. Записываем индекс только при первой встрече.

**Мини-пример.** `[5,2,5] → map[5:0 2:1]`.

**Частая ошибка.** Без проверки каждое повторение перезапишет индекс, и map будет хранить последнюю позицию.

**Сложность.** Ожидаемое время O(n), память O(k).

## 03.3 `ContainsDuplicate` — адаптация LeetCode 217

Оригинал: https://leetcode.com/problems/contains-duplicate/

**Что тренируем.** Используем `map[int]struct{}` как множество.

**Как рассуждать.** Если значение уже есть в `seen`, ответ готов. Иначе добавляем его и продолжаем.

**Мини-пример.** `[1,2,3,1] → true`; `[1,2,3] → false`.

**Частая ошибка.** Сначала полностью строить частоты, хотя задача разрешает завершиться на первом повторе.

**Сложность.** Ожидаемое время O(n), память O(n).

## 03.4 `TwoSum` — адаптация LeetCode 1

Оригинал: https://leetcode.com/problems/two-sum/

**Что тренируем.** Превращаем поиск пары O(n²) в один проход с map.

**Как рассуждать.** Для текущего `value` вычисляем `need := target-value`. Сначала ищем `need` среди прошлых элементов, затем добавляем текущий. Такой порядок не позволяет использовать один индекс дважды.

**Мини-пример.** `[2,7,11,15], target=9 → [0,1], true`.

**Частая ошибка.** Добавить текущий элемент до проверки. При `target == 2*value` функция может выбрать один и тот же индекс дважды.

**Сложность.** Ожидаемое время O(n), память O(n).

## 03.5 `UniqueIntersection` — адаптация LeetCode 349

Оригинал: https://leetcode.com/problems/intersection-of-two-arrays/

**Что тренируем.** Соединяем два множества и детерминированный результат.

**Как рассуждать.** Запишите элементы первого среза в set. При обходе второго добавляйте найденные элементы в отдельный set ответа. Затем перенесите ключи в срез и отсортируйте его.

**Мини-пример.** `[4,9,5,4]` и `[9,4,9,8] → [4,9]`.

**Частая ошибка.** Сразу добавлять каждое совпадение в ответ: повторные `9` создадут дубликаты.

**Сложность.** Ожидаемое время O(n+m+k log k) из-за итоговой сортировки, память O(n+k).
