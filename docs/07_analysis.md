# 07. Анализ: ответ, шаги и сохранность данных

Здесь важно не только получить правильный срез. Тесты проверяют число сравнений, свойства результата и то, менялся ли вход.

## 07.1 `LinearWithSteps`

**Что тренируем.** Связываем проход цикла с числом сравнений.

**Как рассуждать.** Перед каждым `value == target` увеличиваем `Comparisons`. При находке возвращаем индекс, true и текущий счётчик. При отсутствии индекс `-1`, false, число сравнений `len(values)`.

**Мини-пример.** `[1,3,5], target=5 → {Index:2, Found:true, Comparisons:3}`.

**Частая ошибка.** Увеличивать счётчик только при совпадении: он должен показывать все выполненные сравнения.

**Сложность.** Время O(n), память O(1).

## 07.2 `BinaryWithSteps`

**Что тренируем.** Проверяем логарифмический рост не секундомером, а шагами.

**Как рассуждать.** Увеличиваем счётчик один раз для каждой проверенной середины. Для 7 элементов достаточно не более 3 сравнений, чтобы найти крайний элемент.

**Мини-пример.** `[1,3,5,7,9,11,13], target=13` — не более трёх сравнений.

**Частая ошибка.** Считать изменение границы отдельным сравнением с элементом. Счётчик имеет смысл только при заранее выбранной основной операции.

**Сложность.** Время O(log n), память O(1).

## 07.3 `CountInversions`

**Что тренируем.** Видим конкретную задачу с вложенными циклами.

**Как рассуждать.** Для каждой пары `i < j` проверяем, нарушен ли порядок `values[i] > values[j]`.

**Мини-пример.** `[3,2,1] → 3`; `[1,2,3] → 0`.

**Частая ошибка.** Считать пары с одинаковыми значениями инверсиями: условие строгое `>`.

**Сложность.** Простая версия: время O(n²), память O(1).

## 07.4 `IsPermutation`

**Что тренируем.** Проверяем, что сортировка не потеряла и не создала значения.

**Как рассуждать.** Разные длины сразу дают false. Считаем частоты первого среза, уменьшаем их по второму; отсутствующий или исчерпанный ключ даёт false.

**Мини-пример.** `[1,2,2,3]` и `[2,3,2,1] → true`; `[1,2]` и `[1,1] → false`.

**Частая ошибка.** Сравнить только множества ключей и забыть количество повторов.

**Сложность.** Ожидаемое время O(n), память O(k).

## 07.5 `SortedCopy`

**Что тренируем.** Проверяем побочный эффект функции.

**Как рассуждать.** Сначала копируем элементы, затем применяем свою сортировку к копии. Тест сравнивает и результат, и исходный срез.

**Мини-пример.** Вход `[3,1,2]`, результат `[1,2,3]`, вход по-прежнему `[3,1,2]`.

**Частая ошибка.** Присвоение `copy := values` не копирует базовый массив.

**Сложность.** Зависит от сортировки; дополнительная память O(n) обязательна из-за независимой копии.
