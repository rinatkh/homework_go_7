# 08. Итоговые задачи LeetCode

Условия ниже адаптированы и сокращены. Перед решением откройте оригинал по ссылке, проверьте ограничения и примеры, затем закройте вкладку и сформулируйте план своими словами.

## 08.1 `BinarySearch704`

```go
func BinarySearch704(values []int, target int) int
```

Оригинал: https://leetcode.com/problems/binary-search/

**Что тренируем.** Полный бинарный поиск по готовому контракту.

**Подсказка.** Проверьте, что контракт отличается от поиска позиции вставки.

**Мини-пример.** `[-1,0,3,5,9,12], target=9 → 4`.

**Частая ошибка.** Сортировать вход и потерять исходные индексы.

**Сложность.** Время O(log n), память O(1).

## 08.2 `RemoveDuplicates26`

```go
func RemoveDuplicates26(values []int) int
```

Оригинал: https://leetcode.com/problems/remove-duplicates-from-sorted-array/

**Что тренируем.** Два индекса и изменение среза на месте.

**Подсказка.** Используйте факт, что вход уже отсортирован.

**Мини-пример.** `[0,0,1,1,2] → k=3`, полезный префикс `[0,1,2]`.

**Частая ошибка.** Возвращать новый срез вместо длины `k`: тестирующая система смотрит на первые k ячеек исходного массива.

**Сложность.** Время O(n), память O(1).

## 08.3 `MoveZeroes283`

```go
func MoveZeroes283(values []int)
```

Оригинал: https://leetcode.com/problems/move-zeroes/

**Что тренируем.** Сохраняем относительный порядок выбранных элементов.

**Подсказка.** Перестановка с последним элементом может нарушить порядок.

**Мини-пример.** `[0,1,0,3,12] → [1,3,12,0,0]`.

**Частая ошибка.** Менять каждый ноль с последним элементом: нули уйдут вправо, но порядок ненулевых значений изменится.

**Сложность.** Время O(n), память O(1).

## 08.4 `SortedSquares977`

```go
func SortedSquares977(values []int) []int
```

Оригинал: https://leetcode.com/problems/squares-of-a-sorted-array/

**Что тренируем.** Два указателя на концах отсортированного среза.

**Подсказка.** После возведения в квадрат порядок отрицательных значений меняется.

**Ограничение.** Значения от -10 000 до 10 000; вход не меняется.

**Мини-пример.** `[-4,-1,0,3,10] → [0,1,9,16,100]`.

**Частая ошибка.** Просто возвести элементы в квадрат: получится `[16,1,0,9,100]`, то есть порядок нарушится.

**Сложность.** Время O(n), память O(n) для результата.

## 08.5 `MajorityElement169`

```go
func MajorityElement169(values []int) int
```

Оригинал: https://leetcode.com/problems/majority-element/

**Что тренируем.** Выбираем сначала понятное решение через частоты.

**Подсказка.** Строго больше половины не равно как минимум половине.

**Мини-пример.** `[2,2,1,1,1,2,2] → 2`.

**Частая ошибка.** Проверять `>= len(values)/2`: при чётной длине половина ещё не является строгим большинством.

**Сложность.** Ожидаемое время O(n), память O(n). После этого можно отдельно изучить алгоритм Бойера—Мура с O(1) памяти.
