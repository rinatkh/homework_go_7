# 06. Quick Sort: опорное значение и две меньшие задачи

Для первых запусков используйте срез длиной 5–7. После каждого изменения рисуйте границы `left..right`, `scan`, `store` и опорное значение.

## 06.1 `Partition`

**Что тренируем.** Выполняем центральную операцию Quick Sort отдельно от рекурсии.

**Как рассуждать.** Берём `pivot := values[right]`. `scan` просматривает участок, `store` указывает место для следующего значения меньше pivot. В конце меняем pivot с `values[store]`.

**Мини-пример.** `[7,2,9,3,5]` после разбиения вокруг `5` может стать `[2,3,5,7,9]`; индекс pivot равен `2`.

**Частая ошибка.** Включить `right` в цикл сравнений и переместить pivot раньше времени.

**Сложность.** Время O(k) для участка длины k, память O(1).

## 06.2 `QuickSort`

**Что тренируем.** Соединяем базовый случай, разбиение и рекурсию.

**Как рассуждать.** Участок из нуля или одного элемента уже отсортирован. Иначе вызываем Partition, затем сортируем участки строго слева и строго справа от окончательной позиции pivot.

**Мини-пример.** `[5,1,4,2] → [1,2,4,5]`.

**Частая ошибка.** Снова включить pivot в один из рекурсивных диапазонов: границы могут перестать уменьшаться.

**Сложность.** Среднее время O(n log n), худшее O(n²); стек обычно O(log n), в худшем случае O(n).

## 06.3 `QuickSortDescending`

**Что тренируем.** Меняем отношение порядка осознанно.

**Как рассуждать.** В левой части должны находиться значения больше pivot. Все границы и базовый случай остаются такими же.

**Мини-пример.** `[3,1,2] → [3,2,1]`.

**Частая ошибка.** Изменить только финальную проверку результата, но оставить сравнение разбиения `< pivot`.

**Сложность.** Та же, что у возрастающей версии.

## 06.4 `QuickSortCopy`

**Что тренируем.** Различаем сортировку на месте и функцию без изменения входа.

**Как рассуждать.** Создаём независимую копию через `append([]int(nil), values...)` или `copy`, сортируем её, возвращаем копию.

**Мини-пример.** Вход `[3,1,2]` остаётся `[3,1,2]`, ответ `[1,2,3]`.

**Частая ошибка.** Написать `result := values`: это второй заголовок над тем же базовым массивом, а не копия элементов.

**Сложность.** Время Quick Sort плюс O(n) на копирование; дополнительная память O(n) для копии.

## 06.5 `SortArray` — адаптация LeetCode 912

Оригинал: https://leetcode.com/problems/sort-an-array/

**Что тренируем.** Применяем свой алгоритм к внешнему контракту.

**Как рассуждать.** Условие требует сортировку без готовой библиотечной функции и ориентир O(n log n). Для урока используем Quick Sort, отдельно называя его худший случай O(n²).

**Мини-пример.** `[5,2,3,1] → [1,2,3,5]`; повторы `[5,1,1,2] → [1,1,2,5]`.

**Частая ошибка.** Утверждать, что учебный Quick Sort полностью выполняет гарантию худшего времени O(n log n). Для строгой гарантии нужен другой или гибридный алгоритм.

**Сложность.** Среднее время O(n log n), худшее O(n²); стек обычно O(log n).
