# Домашняя работа 7 — алгоритмы, поиск и сортировки

Домашняя работа продолжает классную работу 7 и содержит 40 небольших задач: по пять на каждый раздел. Первые задачи закрепляют одну операцию, последние соединяют несколько идей. Тринадцать задач адаптированы из LeetCode; их условия пересказаны своими словами, а рядом приведена ссылка на оригинал.

## Разделы

| № | Пакет | Что закрепляем | Задач |
|---|---|---|---:|
| 01 | `internal/complexity` | считаем шаги и отличаем O(1), O(log n), O(n), O(n²) | 5 |
| 02 | `internal/search` | линейный и бинарный поиск, первая позиция, место вставки | 5 |
| 03 | `internal/maps` | частоты, индекс, повтор, Two Sum, пересечение | 5 |
| 04 | `internal/insertdelete` | вставка и удаление в срезе, Remove Element, Merge Sorted | 5 |
| 05 | `internal/simplesort` | Bubble, Selection, Insertion, проверка порядка, Sort Colors | 5 |
| 06 | `internal/quicksort` | разбиение, Quick Sort, копия, обратный порядок, Sort an Array | 5 |
| 07 | `internal/analysis` | поиск со счётчиком, инверсии, проверка перестановки, неизменность входа | 5 |
| 08 | `internal/leetcode` | пять итоговых адаптаций LeetCode | 5 |

Подробные задания находятся в `docs/01_complexity.md` … `docs/08_leetcode.md`. У каждой функции есть:

- цель;
- контракт и подсказка без готового алгоритма;
- маленький пример;
- частая ошибка;
- ожидаемая сложность по времени и дополнительной памяти.

## Как решать

1. Откройте документ раздела и одну функцию с `TODO`.
2. До кода проговорите размер входа `n` и ожидаемый результат.
3. Запишите простой вариант на бумаге или в комментарии.
4. Реализуйте только одну функцию.
5. Запустите тесты одного раздела: `make test-search`.
6. После зелёного теста назовите время и дополнительную память.
7. Только потом переходите к следующей функции.

## Как запустить свои решения

```bash
make run-complexity
make run-search
make run-maps
make run-insertdelete
make run-simplesort
make run-quicksort
make run-analysis
make run-leetcode
make run-all
make help
```

Восемь `cmd/01_complexity` … `cmd/08_leetcode` соответствуют восьми пакетам
`internal`. В `main.go` только небольшой вход, вызов существующей функции и
вывод: **Получено / Ожидается**. Поиск, сортировка и другие решения по-прежнему
пишутся в TODO внутри `internal`, не в cmd. `internal/demo` только форматирует
результаты; там нет решений задач.

```bash
make run-search    # увидеть фактическое поведение своих функций
make test-search   # проверить все контракты этого раздела
```

До реализации TODO запускаемые примеры показывают расхождение и сообщение
«Результаты отличаются — проверь реализацию». При совпадении говорится только
о конкретном примере. Запуск завершается с кодом 0, если программа отработала,
включая пример с расхождением: это демонстрация, а не acceptance check.
`run-all` поэтому показывает все восемь разделов. Индекс -1 и nil от заглушки
не используются для небезопасного чтения результата.

Автоматические тесты задач остаются исходными и до решения красные.
`make test-demos` проверяет только запуск cmd и честный формат вывода,
не готовность 40 решений. Эта проверка включена в `make starter-check`;
`make ci` предназначен для полностью решённой домашней работы.

## Проверки

```bash
make compile
make fmt-check
make vet
make test-search
make test
make test-race
make ci
```

Стартовый проект намеренно содержит заглушки: `make compile`, `make fmt-check` и `make vet` должны проходить, а функциональные тесты — падать до реализации TODO. Не меняйте тесты, чтобы «сделать их зелёными»; исправляйте функции.

## Важное правило LeetCode

Не начинайте с поиска готового ответа. Сначала своими словами запишите:

1. Что дано?
2. Что нужно вернуть?
3. Можно ли менять вход?
4. Какой крайний случай самый маленький?
5. Какая сложность требуется?

После решения можно сравнить подход с официальным разбором, но код должен оставаться понятным вам построчно.

## Границы и автономность

Проект использует Go 1.22 и только стандартную библиотеку. Импортировать
classroom или скачивать его тестовые helpers не требуется: общие входы находятся
в собственном `internal/testutil`. Все 40 функций остаются TODO.

`contract_test.go` дополняют исходные `tasks_test.go`: проверяют границы,
повторы, неизменность входа и инварианты, включая не менее десяти входов
для каждой ключевой функции. Первое красное выполнение функциональных тестов
ожидаемо; отсутствие ошибок компиляции не означает готовность решения.

`nil` и пустой срез считаются одинаковыми последовательностями. Обычная
арифметика `int` использует правила Go; проверки переполнения сумм не требуются.
Для TwoSum тестовые числа ограничены так, чтобы арифметика помещалась в int;
для SortedSquares977 предел значения — 10 000. Partition получает только
допустимый непустой диапазон; остальные ограничения указаны в документах задач.

Быстрая проверка стартового проекта: `make starter-check`. `make ci` проверяет
готовое решение, поэтому до реализации TODO ожидаемо завершается ошибкой.
