# Домашняя работа 7 — алгоритмы, поиск и сортировки

Домашняя работа продолжает классную работу 7 и содержит 40 небольших задач: по пять на каждый раздел. Первые задачи закрепляют одну операцию, последние соединяют несколько идей. Тринадцать задач адаптированы из LeetCode; их условия пересказаны своими словами, а рядом приведена ссылка на оригинал.

## Разделы

| № | Пакет | Что закрепляем | Задач |
|---|---|---|---:|
| 01 | `internal/complexity` | считаем шаги и отличаем O(1), O(log n), O(n), O(n²) | 5 |
| 02 | `internal/search` | линейный и бинарный поиск, первая позиция, место вставки | 5 |
| 03 | `internal/maps` | частоты, индекс, повтор, Two Sum, пересечение | 5 |
| 04 | `internal/insertdelete` | вставка и удаление в срезе, Remove Element, Merge Sorted | 5 |
| 05 | `internal/simplesort` | Bubble, Selection, Insertion, проверка порядка, Sort Colors | 5 |
| 06 | `internal/quicksort` | разбиение, Quick Sort, копия, обратный порядок, Sort an Array | 5 |
| 07 | `internal/analysis` | поиск со счётчиком, инверсии, проверка перестановки, неизменность входа | 5 |
| 08 | `internal/leetcode` | пять итоговых адаптаций LeetCode | 5 |

Подробные задания находятся в `docs/01_complexity.md` … `docs/08_leetcode.md`. У каждой функции есть:

- цель;
- последовательность рассуждений;
- маленький пример;
- частая ошибка;
- ожидаемая сложность по времени и дополнительной памяти.

## Как решать

1. Откройте документ раздела и одну функцию с `TODO`.
2. До кода проговорите размер входа `n` и ожидаемый результат.
3. Запишите простой вариант на бумаге или в комментарии.
4. Реализуйте только одну функцию.
5. Запустите тесты одного раздела: `make test-search`.
6. После зелёного теста назовите время и дополнительную память.
7. Только потом переходите к следующей функции.

## Проверки

```bash
make compile
make fmt-check
make vet
make test-search
make test
make test-race
make ci
```

Стартовый проект намеренно содержит заглушки: `make compile`, `make fmt-check` и `make vet` должны проходить, а функциональные тесты — падать до реализации TODO. Не меняйте тесты, чтобы «сделать их зелёными»; исправляйте функции.

## Важное правило LeetCode

Не начинайте с поиска готового ответа. Сначала своими словами запишите:

1. Что дано?
2. Что нужно вернуть?
3. Можно ли менять вход?
4. Какой крайний случай самый маленький?
5. Какая сложность требуется?

После решения можно сравнить подход с официальным разбором, но код должен оставаться понятным вам построчно.
